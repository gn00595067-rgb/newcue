# 測試期 CUE號／訂檔紀錄與每月上限

## 為什麼
開放業務試用申請 CUE號、送出訂檔。Ragic 每月 CUE號上限 99 筆，測試不能吃掉太多，也要能事後找出、清掉測試資料。

## 規則（測試期＝Secrets `RAGIC_TEST_MODE` 未設或非 false）
1. 紀錄表：Ragic `cue/6`「CUE系統訂檔測試」（欄位：訂檔單號 1016200、CUE號 1016201）。
2. 申請 CUE號成功 → cue/6 新增一列（CUE號）。
3. 送出訂檔成功（含部分波段成功）→ 讀回各波訂檔單號，回填到同一 CUE號 那列（多波以「、」串接）；沒有那列（沿用已申請的 CUE號）就新增一列。更新原訂檔不回填。
4. 上限：本月（台北時間、依 cue/6 紀錄建立時間）已有 `RAGIC_TEST_CUE_LIMIT`（預設 15）列 → 「🎫 申請 CUE號」變灰並寫「本月測試 CUE號已達 15 筆上限」；按下時會再查一次最新數字。
   - 畫面顯示「🧪 測試期：本月程式已申請 n／15 個 CUE號」（60 秒快取）。
   - 讀不到 cue/6 → 擋住申請（寧可擋，不超用）。
   - 沿用已申請 CUE號 而新增的列也算進數量（保守）。
5. 測試期送出的訂檔，「需求或狀況說明」開頭加「【newcue 系統測試】」（訂檔表沒有備註欄，這是會寫進訂檔的文字欄）。
6. cue/6 寫入失敗不影響 CUE號／訂檔結果，只顯示提醒。

## 正式上線
Secrets 設 `RAGIC_TEST_MODE="false"` → 不再記 cue/6、不加測試標記、不限次數。
