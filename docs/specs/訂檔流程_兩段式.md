# 訂檔流程：先申請 CUE號，再送出訂檔（兩段式）

> 來源：Jonathan 2026-10-22「送出訂檔仍失敗；理論上應先申請好 CUE號，才知道對應的客戶、產品…，請把流程仔細檢視設計一遍」；細節參考 cueupload。
> 分支：ragic-dev。

## 1. 現況檢視（問題）

| # | 問題 | 影響 |
|---|---|---|
| 1 | 「申請 CUE號」和「建訂檔」綁在同一顆按鈕；CUE號申請成功、訂檔失敗時，程式**沒記住 CUE號** | 同事重按 → 再申請一個 → Ragic 多出孤兒 CUE號（流水號被吃掉） |
| 2 | 多波時第 2 波失敗，第 1 波已建的訂檔沒記錄 | 重送會重建第 1 波 → 重複訂檔 |
| 3 | 訂檔的客戶／產品／業務／主管取自客戶主檔，不是 CUE號申請表 | Ragic 實際：選 CUE號 後由申請表連動帶入（300 筆 95～99% 與申請表相同）；兩邊不一致時以申請表為準才對 |
| 4 | 業務已經在 Ragic 手動申請過 CUE號，程式沒辦法沿用 | 只能再申請一個 |
| 5 | Ragic 回 ERROR 但申請紀錄仍建立（10/21 實測 1150181） | 目前只提示去刪；其實紀錄有效、可直接沿用 |
| 6 | 10/22 截圖仍是舊版畫面（「客戶名稱、主管為必填」10/16 已修） | 測試 app 未 Reboot，跑的是舊模組 |

## 2. 新流程

```
存檔（cue/2，拿到 Cue表模擬編號）
   │
   ├─ 🎫 申請 CUE號 ──→ forms13/4 建申請（客戶編號／名稱／主管／業務／產品／起走日／總波段／模擬編號）
   │                     → 讀回申請紀錄：CUE號、客戶、產品、業務、主管 → 記進快照 cue_apply，立即存回 cue/2
   │     或
   ├─ 沿用已申請的 CUE號 ─→ 以 CUE號 查申請表（where 篩選）→ 客戶編號須與帶入客戶相同 → 記進 cue_apply
   │
   └─ 📨 送出訂檔（需已有 CUE號）→ 各波建訂檔（CUE號＋波段；客戶／產品／業務／主管以申請表為準）
                                   → 每完成一波就記下；中途失敗：已完成的記進快照，重送只補沒完成的
```

- 申請 CUE號、沿用、放棄都要**先存檔且無未存修改**（要用存檔的模擬編號；動作完成立即寫回 cue/2）。
- 已有 CUE號 時客戶又換了 → 擋送出並提示：改回原客戶，或「放棄這個 CUE號」重新申請（放棄不會刪 Ragic 紀錄，要自己去申請表刪）。
- Ragic 回 ERROR 但讀回有 CUE號 → 沿用並提示錯誤內容；讀不到 CUE號 → 顯示紀錄編號請去刪。
- 申請人＝存檔人／登入者，必須對得上 Ragic 使用者名稱（開發者帳號名稱不在 Ragic → 申請人會空白，10/21 1150181 即此）。
- 已訂檔（舊資料只有 booking.cue_id）視同已申請。

## 3. 畫面
訂檔資料區最上方「⓪ CUE號」：
- 未申請：說明＋「🎫 申請 CUE號」按鈕＋「已在 Ragic 申請過？輸入 CUE號 沿用」。
- 已申請：✅ CUE號 1151109｜客戶…｜產品…｜業務…｜主管…（申請表讀回）＋「放棄這個 CUE號」。
- 送出按鈕：沒 CUE號 時停用，提示「先申請 CUE號」。

## 4. 驗收
- 單元：申請成功／ERROR 但有 CUE號／ERROR 無 CUE號；沿用查得到＋客戶相符／不符；送出用申請表的客戶欄；多波第 2 波失敗回傳已完成波段，重送只建第 2 波。
- 真 Ragic：申請 → 讀回 → 送出訂檔；第二次送出更新不再申請。
