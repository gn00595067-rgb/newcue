# 客戶先確認＋開新的 CUE

來源：宜歆「CUE表自動化優化 測試回饋」#7（2026-10-29）
設計決定：Jonathan（2026-10-30）

## 0. 審視
- BA：
  - 業務常沒注意到「Ragic 客戶」欄，直接手打客戶名稱。
  - 到訂檔時才回頭帶入客戶，名稱和統編可能對不上，要重做。
  - 排完一張想排下一張，只能重新整理網頁，還要重新登入。
- PM：兩件小事一起做：① 客戶關卡、② 開新 CUE 按鈕。不改各模式內部表單。
- SA：
  - 沿用 `ragic_ui.customer_picker`、`render_new_customer`、`app._CUSTOMER_TARGETS`。
  - 開新 CUE 用「保留清單」清 session，保留清單以外的全部清掉。
- UX：最容易出錯的是在關卡選了「新客戶」，卻沒有真的新增。所以新客戶也算有選，但訂檔時照舊必須帶入 Ragic 客戶（現有規則不變）。

## 1. ① 這次的客戶（關卡，擋住）
- 位置：選完「製作模式」和「選擇格式」之後、表單之前。
  - 適用：簡易模式、一般CUE、年約季約細CUE、專案CUE、健康視CUE、代理商CUE（解鎖後）。
  - 不適用：CUE 管理、統計。
- 三個選項（radio，**預設不選**）：
  1. **Ragic 既有客戶**：顯示客戶搜尋，帶入後才放行。帶入的客戶名稱、統編、產品會填進下方表單（現有機制）。
  2. **新客戶**：
     - 顯示「➕ 新增客戶到 Ragic」（預設展開）。
     - 新增完成後提示「用上方搜尋帶入」，帶入後改為選項 1 的狀態。
     - 也可以先按「先手填，訂檔前再建」放行。
  3. **先估價，暫不指定**：直接放行，客戶名稱手填。
- 還沒滿足條件時，表單不顯示，只顯示一行說明：「請先選這次的客戶（之後訂檔要用 Ragic 客戶編號）」。
- 已放行時，關卡收成一行摘要：「👤 客戶：C00043 聲寶股份有限公司（Ragic）［更換］」或「👤 客戶：先估價（手填）［更換］」。
- 下列情況自動視為已確認，不再擋：
  - 從「我的 CUE」或 CUE 管理開啟存檔
  - 用「載入舊排程」
- 訂檔規則不變：送出訂檔仍需要 Ragic 客戶編號。選 2 或 3 的人，在訂檔區還是可以就地帶入。

## 2. 🆕 開新的 CUE
- 位置：頁面標題「📺 媒體 Cue 表生成器」右側，所有製作模式都看得到。
- 按下後：
  - 若目前內容有「已修改未存檔」（`_cue_dirty`），先跳確認：「目前內容還沒存檔，確定清空？」［清空］［取消］。
  - 清空後回到目前的製作模式，客戶關卡重新出現。
- 保留（不清）：
  - 登入身分（Ragic 使用者、app 密碼狀態）
  - 主管模式、代理商解鎖、主管設定的下載權限
  - 目前製作模式、選擇的格式
- 清空：其他所有欄位，包括已帶入的 Ragic 客戶、關聯的存檔、回簽檔上傳等。
- 存檔區原有的「開新的 CUE（不再關聯這筆存檔）」改成呼叫同一個功能，行為一致。

## 3. 驗收
- 新開 app 選一般CUE：先看到客戶關卡、看不到表單；選「先估價」後表單出現。
- 帶入 Ragic 客戶後，表單的客戶名稱、統編已填好，關卡收成摘要。
- 從「我的 CUE」開啟存檔：不會被關卡擋。
- 排完一張按「🆕 開新的 CUE」：
  - 欄位全部清空，仍是登入狀態，主管模式也還在。
  - 有未存修改時會先問。
