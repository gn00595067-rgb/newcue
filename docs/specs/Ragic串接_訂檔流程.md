## 目標
業務一律用 CUE 程式產 CUE → 資料結構化存在 Ragic → 營運主管在 CUE 程式內審核 → 自動申請 CUE號 → 自動寫入訂檔表。
訂檔所需的檔次、平台、秒數、走期、實收，直接取自 CUE 程式的計算結果，**不再靠 PDF／圖片辨識**（cueupload 的辨識流程保留給外部／舊 CUE）。

## 資料流（目標）

```
[業務] 選客戶（Ragic 客戶表）→ 做 CUE（任一模式）→ 存檔（暫存，版本 v1）
          ↑ 讀回／線上修改（存 v2、v3…，留異動紀錄）
[業務] 送訂檔：補發票日、現折、退佣、收款日、上傳客戶回簽檔 → 狀態「待審」
[主管] 審核頁：看最新版 CUE ＋訂檔資料 → 退回（附原因）／核准
          核准 → 申請 CUE號（forms13/4）→ 回寫 CUE號 → 每波建訂檔（forms12/17，含收入子表、附件）→ 狀態「已訂檔」
```

CUE 狀態：`草稿` →（送訂檔）`待審` →（核准）`已訂檔`／（退回）`草稿`。
「待審」「已訂檔」狀態下業務不能直接改；已訂檔要改 → 走需求三「檔次調整」產生新版本並重新送審（異動單）。

## 分期

### 第 1 期：客戶資料串接（需求一）＋ 共用 Ragic 底層 — 約 2 天
1. 把 cueupload 的 `ragic_fields.py`／`ragic_write.py`／`platform_map.py` 搬到 newcue（`ragic_booking/`），補 pytest（不打真 API）。
2. 所有製作模式的「客戶名稱／統編」改成：輸入統編或名稱 → 搜尋 Ragic 客戶表 → 選一筆 → 自動帶入客戶名、統編、客戶編號、客戶類別、現折％、退佣（找不到可手打，維持現況）。
3. 「新增客戶」：在 app 內填必填欄 → 寫入客戶表（Ragic 客戶表有原生簽核，新客戶建立後由 Ragic 那邊走原本的流程）。
- 上線後立即有用：少打字、拿到客戶編號（後面訂檔、CUE號必填）。

### 第 2 期：CUE 存檔／讀回／線上維護（需求二、四）— 約 3 天
1. 五種模式都能「存檔到 Ragic」（目前只有一般CUE、代理商）。存的內容改為**計算結果**：逐列平台、區域、秒數、每日檔次、定價、實收（JSON），加上輸入參數，讓讀回不必重算、訂檔可直接取數。
2. 同一份 CUE 再存 = **更新同一筆、版本 +1**（不是新增一筆），異動內容記到「異動紀錄」子表（時間、人、改了什麼）。
3. 「我的 CUE」列表：依業務／客戶／狀態查詢，點開即還原到對應模式繼續編輯。
4. 下載維持現狀，不強制先存檔（Jonathan 確認：有時只想下載看看）。從已存檔版本下載時檔名帶版本號。

### 第 3 期：既有 CUE 檔次調整（需求三）— 約 3 天
1. 選一份已存檔 CUE → 指定日期區間＋平台 → 調整／增加每日檔次（表格直接改）→ 自動重算金額 → 存新版本。
2. 異動紀錄寫明：哪個平台、哪段日期、檔次由 X 改 Y、實收變化。
3. 已訂檔的 CUE 調整後狀態回到「待審」，核准後更新訂檔（或另開異動訂檔，待確認營運流程）。

### 第 4 期：送訂檔、主管審核、自動 CUE號、自動訂檔（需求五、六）— 約 4 天
1. 業務「送訂檔」：補發票開立日、現折、退佣（預設帶客戶主檔）、收款日期、個案狀況、上傳客戶回簽檔（訂檔表必附）→ 必填檢查（沿用 `missing_required_order`）→ 狀態「待審」。
2. 營運主管「審核」頁：列出待審件，看 CUE 預覽＋訂檔資料＋異動紀錄 → 核准／退回（必填原因）。
3. 核准時自動：申請 CUE號（forms13/4，填申請人、客戶編號、起走日、總波段）→ 讀回 CUE號 → 每波建一張訂檔（forms12/17）：收入子表依平台細項彙總檔數、秒數、實收未稅；附件＝CUE Excel＋客戶回簽檔 → CUE號、訂檔流水號回寫到 CUE 存檔。
4. 先做「乾跑預覽」模式（顯示將寫入的內容不送出），確認幾筆無誤再開正式寫入（cueupload 已有此設計）。

## 身分：串 Ragic 帳號
- 做法：登入畫面輸入 Ragic Email＋密碼 → 呼叫 `https://ap16.ragic.com/AUTH?login_type=sessionId&json=1&api` 驗證 → 回傳姓名、Email、所屬群組。app 不保存密碼，只把姓名／群組放在本次登入的 session。
- 群組決定角色：例如 Ragic 群組「營運主管」→ 可審核；其他 → 業務。
- 好處：不用另外管一套帳密；姓名與 Ragic 使用者顯示名一致，訂檔表「申請人／訂檔人」可直接填（目前 SALES_MAP 對不上）。
- 寫入 Ragic 仍用共用 API 金鑰，異動紀錄記登入者姓名（不改用個人身分寫入，較單純）。
- 限制：用 Google 登入 Ragic 的人要先在 Ragic 設一組密碼；有開兩步驟驗證的帳號可能無法用此方式登入（官方文件未說明，需實測）；重新整理頁面要重新登入。
- 工作量：約半天到 1 天，併入第 1 期。
